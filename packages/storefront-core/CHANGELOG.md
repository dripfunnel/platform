# @dripfunnel/storefront-core

## 0.1.0

### Minor Changes

- 1917414: The account's list of orders (#813): `useOrders` (from `./theme`) reads the signed-in shopper's orders from the Shop API's new `orderHistory`, newest first, 20 at a time, with `loadMore`, and each `OrderRow`'s day, item count, payment and total; it is `signedOut` and asks nothing on a preview or in the studio frame. Core's messages add `orders.title`.
- 5bac784: `BaselineCheckout`: core's own checkout, in core's words and look, which `CheckoutBoundary` hands a shopper to once the theme's checkout throws. `smokeShop`, `smokeShopper`, `smokeProductSlug` and `smokeProblems` (from `./guard`): the checkout smoke test's offline Shop API, with a test product and cash on delivery in test mode, the test shopper's details, and the words for a test purchase that didn't complete. A problem a boundary catches before the page has set its reporter (a checkout that throws on its first render) is held and sent once it is, instead of being lost.
- a1aa621: The browse hooks (#307 part 2). `./theme` gains `useProduct` (versions, options with their availability, the chosen version's price, stock and photos, a version's own address `/products/{slug}/{version}/`, and the market's legal details for `LegalNotices`), `useCollection` (with `/collections/all/` as every product), `useCollections`, `useSearch`, `useProducts` and `useListing` (filters with OR within a filter and AND across, sort and the page's cursor in the address, `fetchMore`), and `useMenu`, the merchant's menu.
- 850a862: The browser side of browsing (#307 part 1). `./theme` gains the browser hooks (`useLocation`, `navigate`, `useMediaQuery`, `useReducedMotion`, `useInView`, `useScrollProgress`, `usePointer`), `<Image>` and `<Video>` for the store's own media, `useHead`, and the headless `Checkbox`, `Select` and `SearchField`. `StorefrontProvider` takes the page's `address` for a static build and keeps the store's head (noindex outside the live site); `createShopClient` takes `onError`; `PreviewClosed`, `previewClosedCode` and `setRouterBase` serve core's runtime; breadcrumbs show a separator between crumbs.
- c287047: `./theme` gains `AddToCart` and `BuyNow` (#313 part 2): the theme words and styles them, `useCart` adds or buys now, and each carries a `data-df-action` marker the checkout smoke test finds.
- 5f55290: The cart (#313 part 1). `./theme` gains `useCart` (the Shop API's active order as the only cart state: lines, codes, offers and totals as the engine answers them; `add`, `setQuantity`, `remove`, `applyCode`, `removeCode` and `buyNow`, each shown at once and replaced by the engine's answer), the sealed `OrderSummary` (part `summary`) and the headless `CodeField`. Core keeps the cart and session tokens the Shop API hands out (`storedShopState`, the runtime's client `state`).
- 2854a1f: The checkout controller (#313 part 3). `./theme` gains `useCheckout` (contact → delivery address → delivery → payment → review, the engine deciding what each step needs; placing the order and taking its payment), `PlaceOrder`, the sealed `PaymentElement` (part `payment`), the headless `Form`, `SubmitButton`, `TextField`, `Choices` and `AddressFields`, and `addressDraft` and `orderPath`. The payment adapters load Stripe.js (`@stripe/stripe-js`), Razorpay, Cashfree and PayPal only when the shopper pays with them; express wallets only on a live shop. `installTrustedTypes` takes `paymentHosts`; `guestShopState` is the preview's client state; checkout requires the payment element and the summary where core gave it a price.
- 77f4ea8: Content pages and the blog (#324): the optional routes `contentPage`, `blog` and `blogPost` (`contentRoutes`, `contentAddresses`), which the validator and the gate check once a theme maps them; `useContentPage`, `useBlog`, `useBlogPost` and `useProductCards` (from `./theme`); `seoFor` takes an `article` for a post's Article structured data, and the build snapshot (`catalogueSnapshotSchema`) takes the store's published `posts`, so a build writes each post's page with it. `requiredParts` takes any theme route.
- 47d2988: The publish gate's report now passes when only its advisory checks fail: budgets, no-js and crawl, and the visual diff unless the publish must keep the look (new exports `advisoryChecks` and `blocksPublish`). The failing checks and their words stay in the report, so a build that misses a budget can go live with them as suggestions.
- 2f6390a: `consentStorageKey` (where the shopper's consent choice is kept) and `settleMs` (how long a sealed component's own check waits before its second look) are exported, so the publish gate's check step uses core's values instead of restating them.
- df39afb: The publish gate's blocking-time refusal now shows its three timings and, when the page's weight carries it, the CPU slowdown they were taken at (the new optional `PageWeight.cpuSlowdown`), so a refusal on a slow runner can be told from a heavy theme.
- 0694d4f: `useOrder` (from `./theme`) reads the order `/order/{id}/` names, asking the provider about a card payment still pending, with a bank transfer's details while it is awaited, and `payAgain` for a card payment that hasn't gone through (`useRepay`, the checkout's payment flow for a placed order). `OrderSummary` also takes a placed `order`, listing its lines and what was charged.
- 2fe41c4: The platform blocks (#304 part 2): `createShopClient` sends the store key, language, currency, market, cart and session headers and decodes answers with zod (`query`); `loadStore` and `StorefrontProvider`; `createI18n` with core's English messages; `formatMoney` and `toDecimal` for minor units; the required components `Price`, `ConsentBanner` with `ConsentSettingsButton` and `openConsentSettings`, `PreviewBanner`, `LegalNotices` and `PoweredBy`; `seoFor`; `createAnalytics` with GA4, Google Tag Manager (which needs both analytics and marketing consent) and Meta Pixel, each only after consent, loading scripts only over https from the analytics hosts (Google Consent Mode and Meta's consent call, so a withdrawal reaches the provider's own script) and taking the Shop API's money; the route list and `defineTheme` routes; the font allowlist (`fonts`, `fontStack`) and the WCAG contrast check (`contrastRatio`, `readableOn`); and `@dripfunnel/storefront-core/testing`.
- f0bb8c0: Gift cards, downloads and services (#324): `useCart` adds a gift card with its recipient (`AddToCart` and `BuyNow` take `gift`), applies or removes a gift card's number, and gives the cart's `giftCard` and each line's `gift`; `useProduct` gives the product's `kind` (a gift card's expiry, a download's limit and days, a service's duration and place); `useOrder` gives an order's `giftCard`, `downloads` and `licenceKeys`, and each line's gift recipient. `OrderSummary` shows a gift card's part and what is left after it. `TextField` takes `type="date"`.
- 384ebc0: The publish gate's suites in `./guard` (storefront ARCHITECTURE §4.2 step 3): `runGate` and one function per check (`validator`, `contracts`, `sealed`, `checkout`, `axe`, `budgets`, `no-js`, `crawl`, `content`, `visual-diff`, `edge-cases`) over what the build image's check step saw of a build, each reporting pass or fail in plain words; the catalogue snapshot a publish builds from (`catalogueSnapshotSchema`) and the edge-case catalogue (`edgeCases`). The route contract gains `routeAddresses`, where each core route lives on a live site, and `requiredParts` takes `priced: false` for a page core gave no price to show. `./testing` exports `sealedProblemWords`, which keeps to core's own part and problem names whatever a page reports.
- 4cca81b: The runtime walls (#481 part 2). `storeCsp` and `studioCsp` build a store's and the studio frame's Content Security Policy from a page's `inlineHashes` (never a nonce), and `pageHeaders` gives each HTML file of a build its header for the manifest; `installTrustedTypes` creates the `df-core` and narrow `default` policies, and analytics load their scripts through `df-core`. `<Link>` (now in `./theme`) opens another host in a new tab with `noreferrer noopener` in the studio frame, whose render mode is the new `studio`, and never carries a `javascript:` or `data:` address. `SectionBoundary` falls back to the baseline section and `CheckoutBoundary` switches a shopper to the baseline checkout for the visit, each reporting the failure.
- 5101dbc: Sealed components, branded commerce types and the visibility check (#481 part 1). `Price`, `PreviewBanner`, `PoweredBy`, `LegalNotices`, `ConsentBanner`, `ConsentSettingsButton` and the new `Breadcrumbs` render in a closed shadow root a theme styles only through its `className`, the `--df-*` custom properties and their `::part` names; the consent and preview banners sit in the top layer. `Money`, `Stock`, `Rating` and `Badge` are branded types only core's decoders make (`moneySchema`, `stockSchema`, `ratingSchema`, `badgeSchema`), replacing `ShopMoney`, `shopMoneySchema` and `isShopMoney`; `formatMoney`, `toDecimal`, `Price`, analytics and SEO take `Money`. Each sealed component checks it is seen after layout and reports one that isn't through `setProblemReporter` (the Shop API's `reportStorefrontProblem` under `StorefrontProvider`). `./testing` adds `visibilityProblems`, and `pageProblems` looks for the `data-df-sealed` mark. The validator refuses a cast to a commerce type (`code/core-type-cast`).
- 069c54a: `useSignIn` and `useAccount` (from `./theme`): sign-in by email and password or by an emailed or texted code (which also creates an account or sets a new password), keeping the session for the visit or longer; the signed-in shopper's details and addresses (`makeDefault` sends a saved address as it was saved), with sign-out. `useOrder` also reads an order in the account, `/account/orders/{id}/`. On a preview neither asks the Shop API anything.
- 8a04972: The store's brand and the home page's search and sharing through `useStorefront()` (#471): `loadStore` asks the Shop API for `favicon`, `tagline`, `social` (each network's https profile address; one that doesn't parse as https is dropped) and `seo` (`title`, `description`, `image`), and `ShopStoreSettings` carries them, with the new `StoreSeo` type. The catalogue snapshot (`snapshotStoreSchema`) takes the same fields, each optional, so a publish builds with them.
- 618fafb: `storeCsp` takes an optional `portalOrigin` (an https origin with no path) and lists it in `frame-ancestors`, so the store's portal can show its live site and preview pages in a frame (storefront ARCHITECTURE §3.5); without one the header keeps `frame-ancestors 'none'`. The catalogue snapshot's `csp` carries it.
- 1fdd69b: The studio frame's hot-swap entry point (storefront AI-STUDIO §4 step 5): `studioBasePath` reads `/__studio/{session}/` from core's own module address, `studioShopEndpoint` points the Shop API client under it, `studioPagePath` gives a page's path inside the frame, and `connectHotReload` loads each new bundle the store's Durable Object announces and applies only the newest, keeping the scroll; a failed load is tried again on the next notice, and a dropped socket is opened again after 1 second, doubling to 30.
- 3a29763: The studio frame answers the studio's messages (storefront AI-STUDIO §8): `connectStudioFrame` posts `df-studio:page` with the page's path on every navigation, the first included, and, while the portal's `df-studio:edit` is on, outlines hovered words (a dark dashed ring on a white halo, `studioHoverColors`) and turns a click on them into `df-studio:text` with their content key instead of following it. Messages go only to the portal's origin and are heard only from the portal's window at that origin, which `studioFramePage` writes into the frame's page beside its CSP and `studioPortalOrigin` reads back. `createI18n` takes a `createTextKeys()` map that remembers each theme string it renders with its key (`home:hero.title`; the first key on identical words). Nothing changes in live or preview mode.
- 7381257: A theme's own `t()` keys are accepted by `Translate`, and the media decoders live in a module without `'use client'` so server components can import them.
- c5a17d1: `./guard` gains the upgrade notes and codemod format the upgrade bot applies (storefront ARCHITECTURE §7.1, #485): `upgradeNoteSchema`, `codemodSchema`, `coreUpgradeNotes`, `notesBetween`, `compareVersions`, `applyCodemods`, `changesBetween`, `pinCore`, `baselineWithOwn` and `isThemePath`.
- 5ffa7bb: The validator's code rules (#480 part 2): imports from the allowlist only, no browser globals however they're reached, no walking the DOM, the JSX element and attribute allowlists, no text, address or brand field in code, and `t()` keys written out and present in every language. The new `@dripfunnel/storefront-core/theme` entry is what a theme imports: `useStorefront` and the required components.
- The validator's CSS Module rules (#480 part 3): every selector starts with a module class, and `+` or `~` leads only to another of its classes; no `*`, `html` or `body`; no `:global`, `@import`, `@font-face` or nested rules; `url()` only for the store's media ids (the new `mediaIds` in the context); no `df-` class, element or core attribute; z-index at most 99; transitions and keyframes only of transform, opacity and filter; no words in `content`.
- 9a2f575: The validator, `@dripfunnel/storefront-core/guard` (#480): `validateChange(files, context)` refuses a theme change whole when any file breaks a rule of storefront ARCHITECTURE §3.4, each problem naming the file, the line, a rule id and a plain-words message. This part covers the file allowlist with its caps (200 files, 100 KB a file, 2 MB in all) and symlinks; the content rules (strict JSON, every file and key in every language the store offers, no price, scarcity, urgency, rating or countdown claim, no copied brand field); and `routes.json` against the new `themeRoutesSchema`.
- 17ea2ce: `reportVitals`: real-user Core Web Vitals (LCP, INP, CLS), sent to the store's own `/shop-api/vitals` when a page is left, only if the shopper agreed to analytics (storefront ARCHITECTURE §9, #484).

### Patch Changes

- 5ea5cdb: `compareVersions` and the release-note schema accept a dev prerelease (`0.0.0-dev.7`) and order dev builds by run number.
- 6bad210: The phone check on checkout and on the account address form now matches the API's (a number with its country code, such as +919876543210), so a number the API would refuse is flagged on the form instead of failing the order. Spaces, dashes, dots and brackets are accepted and removed before the number is sent. The message tells the shopper to start with the country code.
- 6701d3f: The sealed order summary stacks each line's name and version as blocks, so a long name no longer runs into its version.
