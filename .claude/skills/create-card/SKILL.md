# Create a card

Follow [docs/code/HOW-TO-WRITE-A-CARD.md](../../../docs/code/HOW-TO-WRITE-A-CARD.md). It is the rule; this is the order to work in.

1. **Read** the docs map, the area's documents, the prototype screen for UI work, the code for a bug, and open cards for duplicates (§3).
2. **Ask** every open question with AskUserQuestion before drafting: kind, outcome, scope, how we'll know it's done, dependencies, plus the task or bug questions in §4. For a bug, keep asking until you have the environment, numbered steps to reproduce, and the expected and actual results. Smallest scope first, recommended option first.
3. **Draft** the whole card from §5–§7: title, issue type, Kind and branch, Folders, Read first, the bug sections, Decided, Do, a complete pasteable **Prompt for Claude**, **Done when** as checkboxes, Not in this item, Needs, and the how-to link. Check it against §9.
4. **Show the draft** and wait for a yes. Then create it as §8 says: the issue with its type, the real number in the branch name, added to DF Platform in BackLog with no assignee unless one was named. Reply with the link.

Never create the card before the draft is approved. Never start a branch or write code for it.
